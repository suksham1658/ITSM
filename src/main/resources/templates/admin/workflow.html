Workflow configuration

A rule decides which workflow a new ticket follows; a workflow is the list of stages (approvals, service desk, implementor, …). Changes apply to tickets submitted after the change.

There are no active rules, so nobody can submit a request. Activate or add a rule below.
You can view the workflow set-up. Only the System Administrator can change it.

Rules: which workflow a ticket follows

Active rules are checked from the lowest priority number up; the first whose condition matches the ticket decides the workflow. Condition keys: ticket_type, category, sub_category, confidentiality, department, priority, each with a list of values, e.g. {"ticket_type":["Service Request"],"department":["Information Technology"]}. All keys given must match; {} matches every ticket (use it for a last catch-all rule).
